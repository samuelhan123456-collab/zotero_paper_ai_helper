## Zotero 论文阅读助手

Zotero 可以按条目组织论文、管理文献，并在内置 PDF 阅读器中阅读、批注和整理笔记。本项目为 Zotero 提供一个可收起的 AI 对话侧栏，方便在阅读过程中解释术语、查找实验条件，以及理解论文的方法与推导。

插件以 `.xpi` 安装包提供。它负责提取论文文字、组织上下文和显示回答；回答由用户自行配置的大模型 API 生成。使用前，需要在设置中填写接口地址、模型名称和 API Key。

## 安装与使用

当前 0.2.4 安装包声明支持 **Zotero 10.x**。在 Zotero 的“工具 → 插件”中打开齿轮菜单，选择“从文件安装插件”，再选择本项目提供的 `.xpi` 文件。

打开一篇 PDF，点击阅读器中的 **AI** 按钮，或展开“论文助手”侧栏。在设置中填好接口信息后即可提问。接口需要兼容 Chat Completions 请求格式；基础地址和模型名称以你的 API 服务提供方说明为准。API 服务的使用权限、额度和费用由用户自行确认。

可以直接输入问题，也可以先选中论文中的词句，再点击“询问 AI”，把原文和问题一起发送。输入框支持 Enter 发送、Shift+Enter 换行。拖动输入框上方的横条可以调整输入区高度，向下拖到一定程度会收起，再向上拖动即可恢复。回答支持复制、停止生成，以及点击页码回到对应位置。

## 两种资料范围

| 模式 | 本轮提供给模型的资料 | 适用场景 |
| --- | --- | --- |
| 仅 PDF | 当前 PDF 中提取并检索到的相关文字，以及需要保留的对话上下文 | 解释选文、查找实验参数、核对论文中的方法与结论 |
| PDF + 联网 | 当前 PDF 的相关文字，加上检索服务返回的外部资料 | 补充背景知识、查找相关研究或术语来源 |

阅读某篇论文时，建议先使用“仅 PDF”，让问题集中在当前文献，并通过页码引用核对回答。这一模式关闭外部资料搜索，提示词要求模型以提供的论文材料为依据。模型仍可能产生错误或引用不当，检索也可能遗漏相关段落，因此回答的可靠性仍需结合原文判断。

补充材料如果包含在当前 PDF 中，可以与正文一起检索。独立的 Supplementary Materials 文件需要先在 Zotero 中打开，再针对该文件提问；当前版本不会自动读取同一条目下的所有附件。

## 技术实现

插件的主要流程是：**提取 PDF 文字 → 按问题选择相关片段 → 组合问题与上下文 → 调用模型 API → 显示回答和引用。**

1. **本地文字提取。** 从 Zotero 阅读器中的 PDF 文本层读取各页内容，并保留页码信息。当前版本主要处理文字层，不把整页图像发送给模型；扫描件需要先完成 OCR。
2. **按片段检索。** 将文字分成带少量重叠的片段，根据问题关键词、选中原文和当前页进行筛选。当前实现使用本地关键词检索，无需额外的向量数据库或嵌入模型接口。每次请求只发送预算范围内的相关片段，模型通常不会看到整篇 PDF。
3. **明确选文指代。** 用户选中词句时，优先加入选文本身和所在页的附近内容，并把“这个词”“这段话”等指代与选文对应起来。新的选文问题默认独立处理；明确提及之前的对话时，再加入有限历史，减少旧话题对本次回答的干扰。
4. **接口与流式输出。** 通过 HTTP 调用配置地址下的 `/chat/completions`，使用流式响应逐步显示回答，并支持取消请求。输入预算和输出上限可在设置中调整；token 估算用于控制资料长度，实际用量以服务端返回值为准。设置页的连接测试读取 `/models`，模型列表可访问不等于所有聊天请求都一定成功。
5. **独立的联网检索。** 联网资料由插件调用检索服务获取，再作为上下文交给模型。默认支持 Crossref 的学术题录与部分摘要；Tavily 网页搜索需要另行配置密钥。题录、摘要和网页摘录的覆盖范围有限，不能当作已读取原文全文。
6. **回答展示。** 使用 Markdown 排版和 KaTeX 显示公式，并对生成的 HTML 进行清理。回答中的资料编号映射到实际提供的片段，PDF 引用可点击跳转；“详情”中可以查看本轮来源、资料覆盖范围和用量信息。短选词回复还会检查是否提到所选术语或其缩写，这项检查只能提示部分偏题情况，不验证事实正确性。

系统提示词默认要求简洁作答，通常先用 1–3 句话回答核心问题；用户明确要求详细解释或推导时，再展开必要步骤。
